UrlAsMarkdown

Any web page → clean Markdown, from your prompt.

A PowerShell 7 module that fetches a page, throws away the chrome, and hands you Markdown worth pasting into an LLM context window. One command. No dependencies.

# Why Markdown Wins

Every token you spend on <div class="wrapper"> is a token you
don't spend on thinking.

## The short version

- Structure survives the trip
- Navigation, cookie banners and scripts do not
- Tables stay tables

PS> Get-UrlAsMarkdown $url -Save -IncludeSource
    Directory: C:\notes
    blog-why-markdown.md    4.2 KB

PS>

Why it exists

Pasting a raw web page into a model wastes context on markup and navigation, and often buries the part you actually wanted. This does the boring cleanup, predictably, from the shell you already have open.

Content, not chrome

Prefers <main> or <article>, then strips scripts, styles, nav, headers, footers, and the usual cookie / newsletter / sidebar furniture.

Structure preserved

Headings, ordered and unordered lists, tables with header separators, blockquotes, links, bold, italics, inline code and fenced blocks all survive.

Nothing to install

No HTML parser, no NuGet package, no network dependency beyond the page itself. Just regex and System.Net.WebUtility on stock PowerShell 7.

Pipeline native

Returns a string by default so it composes with Set-Clipboard, Out-File, or anything else. Accepts URLs from the pipeline. Writes files only when asked.

| Free | 60/min |

Use `<div>`.



 

Note the two easy things to get wrong: the header separator row is sized to the header, and an escaped &lt;div&gt; decodes to literal text instead of being swallowed by the tag stripper. Both are covered by tests.

Install

PowerShell finds modules by folder name, so the folder that lands on your module path must be called UrlAsMarkdown.

Copy the module folder

pwsh 
PS> git clone https://github.com/michaelsanford/UrlAsMarkdown.psm1.git
PS> Copy-Item .\UrlAsMarkdown.psm1\UrlAsMarkdown -Recurse `
       -Destination "$HOME\Documents\PowerShell\Modules\"

Or symlink a working clone

pwsh 
PS> New-Item -ItemType SymbolicLink `
       -Path   "$HOME\Documents\PowerShell\Modules\UrlAsMarkdown" `
       -Target "<clone>\UrlAsMarkdown"

No Import-Module and no profile edit: the manifest declares its exported function, so PowerShell autoloads it the first time you call it.

Usage

ParameterWhat it does
-UrlThe page to convert. Accepts pipeline input, by value or property name.
-OutputPathFile to write. Implies -Save.
-SaveWrite a file; without -OutputPath the name comes from the URL slug.
-IncludeSourcePrepend a > Source: <url> line.
recipes 
# straight to the clipboard, ready to paste into a model
PS> Get-UrlAsMarkdown $url | Set-Clipboard

# a folder of reference docs, each named from its slug
PS> $urls | Get-UrlAsMarkdown -Save -IncludeSource

# one file, explicitly named
PS> Get-UrlAsMarkdown $url -OutputPath notes\api.md

# see what it is doing
PS> Get-UrlAsMarkdown $url -Verbose
VERBOSE: Fetching: https://…
VERBOSE: Converting to Markdown...

Honest limits

The converter is regex-based, not a DOM parser. That is what keeps it dependency-free and fast, and it is also the trade: nested lists are flattened, tables inside tables are not handled, and pathological markup can convert imperfectly. For most articles and documentation pages it is exactly what you want. For scraping arbitrary hostile HTML, reach for a real parser.
